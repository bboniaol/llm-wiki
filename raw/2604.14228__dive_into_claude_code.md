## 1. 核心结论（一句话）

Claude Code 是一个以 **极简 while-loop 为核心、98.4% 代码为运维基础设施** 的 agentic 编码工具；其设计哲学围绕五大人类价值展开，通过十三项设计原则映射到具体实现，并与开源系统 OpenClaw 形成鲜明对比，揭示了部署上下文如何决定架构选择。

---

## 2. 五大人类价值 → 十三项设计原则

| 价值 | 设计原则 | 核心问题 |
|------|----------|----------|
| **人类决策权威** | deny-first + human escalation; graduated trust; append-only state; externalized policy; values-over-rules | 谁拥有最终决定权？ |
| **安全/隐私** | defense in depth; deny-first; reversibility-weighted risk; isolated subagent boundaries | 如何防止伤害？ |
| **可靠执行** | context-as-scarce-resource; append-only durable state; graceful recovery; isolated subagents | 如何保持长期一致性？ |
| **能力放大** | minimal scaffolding; composable extensibility; reversibility-weighted risk; context management | 如何最大化单位产出？ |
| **上下文适应性** | transparent file-based memory; composable extensibility; graduated trust; externalized policy | 如何适应用户特定环境？ |

**关键发现**：AI 决策逻辑仅占代码库 **1.6%**，其余 98.4% 为权限、上下文、扩展、持久化等运维基础设施。

## 4. 六大子系统深度解析

### 4.1 Turn Execution（第4节）— Agentic Query Loop
- **架构选择**：简单 while-loop，非显式状态图（对比 LangGraph）
- **五阶段**：Query Pipeline → Tool Dispatch → Pre-Model Context Shapers → Recovery → Stop Conditions
- **设计原则**：minimal scaffolding with maximal operational harness; graceful recovery

### 4.2 Tool Authorization（第5节）— 权限与安全
- **Deny-first 规则**：deny > ask > allow，未知动作默认上报人类
- **七层权限模式**：从 fully automatic 到 require approval
- **ML-based Auto-Mode Classifier**：自动评估动作风险
- **四层防御**：permission rules + PreToolUse hooks + auto-mode classifier + shell sandboxing
- **关键安全漏洞**：CVE-2025-59536 (CVSS 8.7), CVE-2026-21852 (CVSS 5.3)

### 4.3 Extensibility（第6节）— 四种扩展机制
| 机制 | 层级 | 上下文成本 | 用途 |
|------|------|-----------|------|
| **MCP** | 外部进程 | 高（完整 schema） | 工具注册 |
| **Plugins** | 内部注册 | 中 | 技能/命令扩展 |
| **Skills** | 用户自定义 | 低 | 领域特定工作流 |
| **Hooks** | 生命周期拦截 | 最低 | 策略修改 |

**设计原则**：composable multi-mechanism extensibility; externalized programmable policy

### 4.4 Context Management（第7节）— 五层压缩管道
上下文窗口（200K→1M）是绑定资源约束。五层压缩按成本递增执行：

1. **Budget reduction** — 单个工具输出超限截断
2. **Snip** — 时间深度管理
3. **Microcompact** — 缓存开销优化
4. **Context collapse** — 超长历史折叠
5. **Auto-compact** — 语义压缩（最后手段）

**CLAUDE.md 四级层次**：Project → Local → User → Global，透明文件化配置。

### 4.5 Subagent Delegation（第8节）— 多智能体编排
- **Agent Tool**：Explore、Plan、通用子代理
- **隔离架构**：worktree 隔离，子代理权限受限
- **Sidechain Transcripts**：子代理结果以摘要文本返回父代理

### 4.6 Session Persistence（第9节）— 持久化设计
- **Append-only JSONL transcripts** (`sessionStorage.ts`)
- **Resume/Fork/Rewind** 支持
- **关键安全选择**：session-scoped permissions **不**序列化到 transcript，resume 时从 CLI 参数重建

## 5. Claude Code vs OpenClaw 对比（第10节）

| 维度 | Claude Code | OpenClaw |
|------|-------------|----------|
| **系统范围** | 临时 CLI 进程，单仓库会话 | 持久 WS 网关守护进程，多通道控制平面 |
| **信任模型** | 每动作 deny-first + ML 分类器；7 种权限模式 | 网关边界信任；DM 配对 + 白名单；可配置沙箱 |
| **Agent 运行时** | `queryLoop()` 作为系统中心 | Pi-agent 嵌入网关，RPC 调度 |
| **扩展架构** | 4 种机制（MCP/plugins/skills/hooks） | Manifest-first 插件系统；12 种能力类型 |
| **记忆与上下文** | CLAUDE.md 4 级 + 5 层压缩 | AGENTS.md/SOUL.md/TOOLS.md 等 7+ 文件；混合搜索 |
| **多智能体** | 任务委托子代理，worktree 隔离 | 多智能体路由 + 子代理委托（最大嵌套 5） |

**核心洞察**：相同的设计问题在不同部署上下文中产生截然不同的架构答案——Claude Code 将信任边界放在模型与执行环境之间，OpenClaw 将其放在网关边界。

## 6. 六大未来方向（第12节）

1. **Silent Failure & Observability-Evaluation Gap** — 生成器-评估器分离是否应内置在 harness 中？
2. **跨会话持久化** — 如何在 CLAUDE.md 透明性和长期记忆之间取得平衡？
3. **Harness 边界演化** — Where/When/What/With Whom 四个维度的扩展
4. **Horizon Scaling** — 从单次会话到科学项目级别的长期规划
5. **大规模治理与监督** — 外部治理约束如何影响权限层级？
6. **长期人类能力保留** — 短期放大是否以长期能力退化为代价？

## 7. 关键数据点

- **27%** 的 Claude Code 辅助任务是"没有该工具就不会尝试的工作"（Huang et al., 2025）
- **93%** 的权限提示被用户批准（Hughes, 2026）→ 重构为边界内自动模式而非逐动作审批
- **17%** AI 辅助条件下开发者理解测试分数下降（Shen and Tamkin, 2026）
- **1.6%** AI 决策逻辑 / **98.4%** 运维基础设施（社区源码分析估计）
